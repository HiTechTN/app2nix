📦 app2nix Documentation

Convert any Linux package — .deb, .rpm, .AppImage, Flatpak, Snap, tarball — into a native NixOS expression with one command.

v3.0.0 Stable Python 3.11+ CLI + GUI + API

Overview #

app2nix is a universal package converter for NixOS. It takes packages from mainstream Linux formats and produces production-ready Nix expressions. No more manual dependency hunting.

📦 package.deb

→
📋 Resolve

📄 default.nix

Key Features

  • Universal formats — .deb, .rpm, .AppImage, Flatpak, Snap, tar.gz
  • Auto-dependency resolution — maps 150+ libraries to Nixpkgs
  • Auto-PatchELF — automatic rpath fixing and binary patching
  • Three interfaces — CLI, Web UI (Starlette), Desktop GUI (PyQt6)
  • REST API — integrate into your own tools and pipelines
  • Docker support — ready-to-use container image on ghcr.io

Installation #

Requirements

  • Linux with glibc (x86_64, aarch64, i686, armv7l)
  • Python 3.11 or later
  • dpkg-deb (for .deb packages)

Quick Start #

Convert a .deb package

bashapp2nix convert package.deb

Generates default.nix in the current directory.

Generate also a flake.nix

bashapp2nix convert package.deb --flake

Start the Web UI

bashapp2nix serve
# Open http://localhost:8000

Launch the Desktop GUI

bashapp2nix gui
💡 GUI requirement — The GUI requires PyQt6. Install with pip install "app2nix[gui]".

Install the generated package on NixOS

bash# User install
NIXPKGS_ALLOW_UNFREE=1 nix-env -i -f default.nix

# Or add to /etc/nixos/configuration.nix:
# environment.systemPackages = with pkgs; [
#   (callPackage ~/nix-packages/myapp {})
# ];
sudo nixos-rebuild switch

Examples #

Convert a .deb (Firefox)

bashapp2nix convert firefox_136.0_amd64.deb -d ./firefox-nix
cat ./firefox-nix/default.nix

Convert with flake output

bashapp2nix convert discord.deb --flake -d ./discord-nix
ls ./discord-nix/
# default.nix  flake.nix

JSON output

bashapp2nix convert code_1.96_amd64.deb --json | jq '.nix_dependencies'

Batch conversion

bash#!/usr/bin/env bash
for pkg in *.deb; do
  name=$(basename "$pkg" .deb)
  app2nix convert "$pkg" -d "./nix-packages/$name"
done

RPM conversion

bashapp2nix convert package.rpm --output-dir ./myapp

AppImage conversion

bashapp2nix convert MyApp.AppImage -d ./myapp-nix

Using the generated expression

bash# User install (current profile)
NIXPKGS_ALLOW_UNFREE=1 nix-env -i -f default.nix

# System-wide (NixOS)
# Add to /etc/nixos/configuration.nix:
#   environment.systemPackages = with pkgs; [
#     (callPackage ./path/to/default.nix {})
#   ];
sudo nixos-rebuild switch
💡 Pro tip — For CI/CD pipelines, use --json to parse results programmatically with jq.

The project is organized as a Python package under src/app2nix/:

ModuleResponsibility
cli.pyTyper CLI — convert, serve, gui commands
server.pyStarlette web server with REST API
config.pySettings via pydantic-settings
models.pyPackageInfo, ConversionResult (pydantic)
core/analyzer.pyUniversalAnalyzer — dispatches to format-specific analyzers
core/analyzers/Format parsers: deb, rpm, appimage, flatpak, snap, tarball
core/resolver.pyDependencyResolver — maps 150+ libraries to Nixpkgs
core/generator.pyNixGenerator — produces default.nix, flake.nix, install scripts
core/validator.pyNix syntax validation via nix-instantiate
gui/PyQt6 desktop GUI with QThread workers, i18n, themes

Conversion Pipeline

  1. Analyze — Extract metadata from the package (dpkg-deb for .deb, rpm2cpio for .rpm, unsquashfs for AppImage, etc.)
  2. Detect binaries — Find ELF executables and shared libraries
  3. Extract dependencies — Run ldd and patchelf --print-needed on each binary
  4. Resolve — Map each library to its Nixpkgs package name via the built-in 150+ entry dictionary (+ API and fuzzy matching)
  5. Generate — Render a production-ready default.nix (and optionally flake.nix) using Jinja2 templates
  6. Validate — Check syntax via nix-instantiate --parse (if nix is installed)

Troubleshooting #

Missing dependencies in generated Nix

Some libraries may not be in the built-in mapping (150+ entries). Check unresolved deps with --print-deps and search for them manually:

bashnix search nixpkgs "libfoo"
# Then add them to your Nix expression manually

patchelf: not found

Install patchelf on your system:

bash# Debian/Ubuntu
sudo apt install patchelf

# NixOS
nix-shell -p patchelf

dpkg-deb: not found

For .deb packages, install dpkg:

bashsudo apt install dpkg

nix-build errors

  • autoPatchelfHook errors → run patchelf --print-needed on the binary and add missing libs to buildInputs
  • Unfree license → set NIXPKGS_ALLOW_UNFREE=1
  • Unsupported system → set NIXPKGS_ALLOW_UNSUPPORTED_SYSTEM=1

Web UI won't start

bash# Check if port is in use
sudo lsof -i :8000

# Run with debug mode
APP2NIX_DEBUG=true app2nix serve

# Generate a secret key
python3 -c "import secrets; print(secrets.token_urlsafe(32))"

FAQ #

Q: What formats are supported? — .deb, .rpm, .AppImage, Flatpak (.flatpak), Snap (.snap), and tarballs (.tar.gz, .tgz, .tar).
Q: Do I need NixOS to use app2nix? — No. The CLI and API work on any Linux distribution. Only installing the generated package requires Nix/NixOS.
Q: Can I convert packages from a URL? — Yes. Both the CLI (app2nix convert URL) and the Web UI support URL download.
Q: Does it work for proprietary/closed-source packages? — Yes. app2nix handles any binary package regardless of license. Set NIXPKGS_ALLOW_UNFREE=1 to install.
Q: How accurate is the dependency resolution? — The built-in dictionary covers 150+ common libraries. For unknown libraries, a fuzzy matching algorithm tries to find the closest Nixpkgs name. Unresolved deps are reported and can be added manually.
Q: Can I use app2nix in CI/CD? — Yes. The --json flag outputs machine-readable results. See the CI/CD section for examples.
Q: How do I contribute? — Fork the repo, create a feature branch, and submit a PR. Report bugs via GitHub Issues.
